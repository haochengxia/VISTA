# vqsim and the VQ study

- `vqsim.c`: the C simulator of the virtual-queue (VQ) design space, exact with `src/vista/benchmarks/cachelab/sandbox/vq.py`. It has three modes: cold, handover (S3-FIFO serves the prefix), and online (the live cache switches design; miniature simulations or a given schedule). Build it with `cc -O2 -o vqsim vqsim.c`; the usage is at the top of the file and in `run_online`.
- `vqcore.h`: the design engine itself (stages, ghost, eviction scan, takeover), shared by `vqsim.c` and `vqonline.h`. It also has an experimental TinyLFU-style admission gate (`gate=G gmode=0|1|2 gwin=W`: a count-min sketch compares objects with the tail of the main stage G; 0 rescues objects about to leave from other stages, 1 filters promotions into G as W-TinyLFU does, 2 does both). It is off by default, in `vqsim` only (cold, handover and online runs; not in `vqonline.h`), and not in v1. The reuse-distance rule (`rd=X rdmode=M`) is compiled in only when `VQ_RD` is defined (`vqsim.c` does): objects keep their last gap between requests, and a move up, a ghost admission into main or a rescue is judged by the predicted wait for the next request against X times the residence time of the stage the object would enter. It widens the object record to 24 bytes, so `vqonline.h` rejects such designs.
- `vqonline.h`: the deployable online selector (`OnlineV1` in `vq.py`) in C, keyed by 64-bit object ids, for embedding in other simulators or a live cache. Object records are reused, so memory is bounded by the cache and ghost sizes. `vqonline.c` runs it over a trace of uint64 keys (`cc -O2 -o vqonline vqonline.c`; `vqonline <keys.u64> <candidates.txt> <capacity> [period= start= from= rate= min= margin=]`). A test checks it makes `vq.py`'s decisions exactly.
- `vqonline_v1.h`: the frozen v1 candidates as C strings (a test checks them against `v1/portfolio.json`).
- `libcachesim/`: `OnlineV1` as a libCacheSim eviction algorithm (`onlinev1`). `install.sh <libCacheSim checkout>` copies the engine in and registers it; build libCacheSim as usual and run with `--ignore-obj-size 1` (unit size; the cache size is a number of objects). `lcs_misses.c` prints exact miss counts and run times of libCacheSim algorithms on an oracleGeneral trace; on the parity traces, libCacheSim's `onlinev1` gives exactly `vqonline`'s misses.
- `study/`: the host scripts behind the version-1 results, kept as they ran on the node (paths `/mydata/vq`, `/mydata/vqsim3`).
  `vq_gap.py` (where 3L-Cache still beats v1), `vq_gate.py` (gated designs, handover runs) and `vq_gate_online.py` (the online selector with gated designs) `vq_rd.py` (the reuse-distance rule, handover runs) and `vq_switchcost.py` (the selector's losses at the split and at switches) came after v1; they read train data only. The online mode's `takeover=3` (with `VQ_RD`) merges the old stages by entry time at switches. `vq_run3.py` takes a chunk size to spread a cell's designs over processes, and `vq_portfolio.py` takes extra design sources as `NAME=designs.jsonl`. `vq_portfolio.py` also has `CV_BY=dataset` (leave one dataset out instead of 5 folds by trace).
- Pool screening (after v1, train only so far): the online mode's `pool=FILE screen=M` has the selector log its sampled prefix and, at the split, replay it through a miniature of every design in FILE, adding the M with the fewest sampled misses as warm candidates (exactly as if they had been candidates from the start; tested). `logcap=N` bounds the log to the last N sampled requests; a wrapped log is replayed for every candidate, and scores the same way for all of them. `vq_portfolio_real.py` takes these as `K:RATE:MIN:MARGIN:TAKEOVER:SCREEN:LOGC:LOGMIN` with `POOL=` a file of configs or `cv:PORTFOLIO_CV.json:LO:HI` (each trace's own CV portfolio members), and reports the log's size and the replay's cost.
- Switching-cost options (development, none helped; `v2/logs/dev-switching.txt`): `trial=H` tries each switch first on a miniature mirror of the live cache, replaying the requests since the snapshot H decision points back (`trialsplit=0` exempts the split's takeover); `reseed=1` has every miniature take over the mirror's cache at the split. `vq_portfolio_real.py` takes them as spec fields 10 (TRIAL; negative = split exempt) and 11 (RESEED).
- `v1/`: the frozen version-1 portfolio, the seed designs, the board picks, the ghost-depth sweep and the aggregate logs. Logs carry no trace names.

The write-up is in `docs/cachelab-v1.md`.
